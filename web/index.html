This is the functional layer only. It works out speeds, degrees of freedom, gear centres and shift schedules — everything that needs no parts library. Placing the gears, building a frame to hold them and exporting a model still run on the command line; see the repository.

Claude Code can drive it. The engine ships as a skill — describe a mechanism in words and it writes the description, runs the checks and builds the model. Two commands:

/plugin marketplace add sstriker/brickmesh
/plugin install brickmesh@brickmesh

That fetches the skill from the repository and keeps it up to date with /plugin marketplace update. The engine itself is a separate install, because the skill is instructions and the engine is a program: go install github.com/sstriker/brickmesh/cmd/brickmesh@latest. Without it the skill can still design and check a mechanism; it needs the engine to place the gears and write the file.

To read it before installing anything, or to put it somewhere by hand, SKILL.md is published here and brickmesh-skill.zip unpacks into ~/.claude/skills/.

The parts data is published here too, for anything that wants it: catalog.bin is where every common part's holes and pins are, and meshes.bin is their geometry as indexed triangles, laid out to be fetched a part at a time by byte range. They carry the libraries' terms rather than this page's — see LICENSE.txt, published beside them.
